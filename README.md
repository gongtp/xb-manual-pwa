# 异度资料库

面向《异度神剑》三部曲的任务资料整理、导入与缺漏核验工具。

《异度神剑 1》的委托人目录收录 176 名人物（本篇 140、《相连的未来》36），关联 326 个任务。终极版简中补充资料保存在 `data/xc1-npc-supplement.json`，同名路线委托人修正在 `data/xc1-giver-corrections.json`；导入器会校验具名与特定身份委托人的覆盖情况。更新已有数据库时仅修正已知旧委托人和追加分支说明，保留标记、手动备注与其他任务字段。

## 当前收录

- 按作品、篇章、任务类型、地区、限时/互斥和任务标记筛选；《异度神剑 1》可单独查看本篇与《相连的未来》，《异度神剑 2》可单独查看本篇、扩展票与《黄金之国伊拉》，《异度神剑 3》可单独查看本篇、扩展票追加内容与《崭新的未来》
- 《异度神剑 1》任务列表标记限时与互斥风险，并显示同一互斥组中无法同时完成的任务名称和编号
- 任务支持“未完成”“已完成”以及自定义彩色标签，可在列表最后一列快速标记或取消标记；没有任务使用的自定义标签可以删除
- 搜索任务编号和中文/英文名称
- 查看缺字段、待核验和来源冲突记录
- 手动新增与编辑任务资料；任务流程/核验备注支持 Markdown 编辑与预览
- 每部游戏拥有独立的二级资料功能；“玩法笔记”支持多篇 Markdown 笔记、分类、置顶、排序、搜索和预览
- 导入 CSV / JSON，并按任务编号更新记录
- 导出 JSON 备份
- 使用轻量 SQLite 数据库持久化保存任务

《异度神剑 1》的“地区与地点”已提供终极版简体中文地图册，收录 26 个地区条目、485 个地点：本篇 431 个、《相连的未来》54 个，包含 20 处秘境。支持篇章切换、中英文搜索、地标/地点/秘境筛选、探索状态、收藏、首次发现奖励、附近地标和任务/NPC 关联。监狱岛初访与再访、两个篇章的皇都分别记录。

地点分布图使用游戏数据的 X/Z 坐标等比例投影，提供位置参照；不包含地形、楼层隔断或步行路线。探索与收藏只用于本资料库，不与游戏存档同步，保存在独立的 `xc1_location_progress` 表中。地点目录为只读 JSON，不会修改其他作品或任务记录。

地名来自[蒙纳多研究本部的简体中文本地化数据库](https://xenoblade.cn/模块:RequestHelper)，分类、坐标与奖励对应 [Xenoblade DE 地点数据表](https://xenobladedata.github.io/xb1de/bdat/bdat_common/landmarklist.html)。目录排除了未使用的旧巨神肩场景及事件用皇都副本，保留实际存在但无发现奖励的机神兵残骸遗迹。

重新生成地点目录可运行 `python scripts/fetch_xc1_locations.py --refresh`；源文件缓存在 Git 忽略的 `work/xc1-locations-cache` 中，只更新 `data/xc1-locations.json`。不带 `--refresh` 时复用缓存。

《异度神剑 1》当前收录《终极版》完整任务目录 523 条：本篇 480 条、《相连的未来》43 条，并记录英文检索名、任务分类、限时/互斥、接取信息、目标、奖励和风险提示。本篇中文名称优先采用蒙纳多研究本部：376 条独立页面通过游戏内部任务编号与英文数据表交叉对应，其余条目直接核对该站使用的简体中文本地化数据库和公开的《终极版》游戏数据表；当前 523 条均已完成资料核验。

《异度神剑 2》当前收录 493 条：本篇 383 条、扩展票 52 条、《黄金之国伊拉》58 条。其中包含 15 条主线任务、163 条普通任务、32 条异刃任务、274 条佣兵团任务和 9 条特殊事件。资料以乐园数据管理室为主，并与 Xenoblade Wiki 的任务、佣兵团和 DLC 目录交叉核对。扩展票统计为 26 条任务和 26 条佣兵团任务；免费更新追加的“余恨”归入本篇，并在核验备注中明确标识，不计入付费扩展票。《异度神剑 2》不使用限时与互斥属性。

《异度神剑 2》的“角色与异刃”提供立绘图鉴，按 Switch 原版本篇、扩展票和《黄金之国伊拉》分别收录具名可控角色、史诗/稀有异刃与觉醒状态。可搜索简体中文名、英文名和技能，并筛选属性、职责、获取方式、收集和收藏状态；详情包括武器、获取条件、场景技能、战斗技能、喜好、固定搭档与关联任务。临时可控角色、无法获得的灭和重复觉醒状态有明确说明，不能作为独立收集目标。花的属性与职责显示加入时配置，可在游戏中定制。

名称和结构化资料逐页核对[乐园数据管理室的御刃者目录](https://xenoblade2.cn/御刃者)、[异刃目录](https://xenoblade2.cn/异刃)及伊拉人物页面，并用 [Nintendo 更新记录](https://en-americas-support.nintendo.com/app/answers/detail/a_id/28012/p/897)核对免费更新与扩展票范围。真实人物图片保存在 `public/images/xc2/`，每条档案记录图片及资料来源。普通随机异刃不逐个建档，Switch 2 Edition 的新增内容不计入这批原版目录。收集与收藏仅用于本资料库，保存在独立的 `xc2_character_progress` 表中，不与游戏存档同步。

重新生成角色目录可运行 `python scripts/fetch_xc2_characters.py`；目录保存在 `data/xc2-characters.json`，源页面缓存位于 Git 忽略的 `work/xc2-characters-sources/`。更新资料不会覆盖收集、收藏或其他任务与笔记记录。

《异度神剑 3》当前收录 246 条：本篇 198 条、扩展票追加 6 条、《崭新的未来》42 条；按类型统计为 12 条主线剧情、42 条英雄任务和 192 条普通任务。资料优先逐页采用送行者的收集手册，并用 Xenoblade Wiki 的任务分类目录交叉核对。主站普通任务目录中的“让艾塞尔成长”详情页返回 404，且该事件不会进入游戏任务日志，因此单独以 Gamer Guides 与 GameFAQs 补齐并在条目中明确标注。全部任务均记录条件、奖励、推荐等级与 Markdown 流程；《异度神剑 3》不使用限时与互斥属性。

《异度神剑 1》的一级任务类型统一为“支线任务”“剧情任务”“突发任务”。讨伐、强敌、素材、收集、搜寻等保留为目标分类；限时和互斥属于可与任务类型重叠的属性，不作为一级类型。突发任务按满足条件后自动触发的口径核验，本篇 12 条、《相连的未来》2 条。

## 数据存储

- 数据库使用 Node.js 自带的普通 SQLite，固定文件为 `data/xeno-archive.sqlite`
- 数据库连接不再依赖 Cloudflare D1 或 Miniflare；可通过环境变量 `SQLITE_DATABASE_PATH` 指定其他 SQLite 文件
- 首次启动时会自动建表，并从 `data/xc1-quests.json`、`data/xc2-quests.json` 和 `data/xc3-quests.json` 导入共 1262 条初始任务
- 玩法笔记保存在独立的 `game_notes` 表中，首次打开会写入《异度神剑 1：全任务完成注意事项》示例笔记
- 限时、互斥、互斥组和路线使用独立字段保存；核验备注可以自由修改，不会改变这些筛选属性
- 手动备注使用独立字段保存，并在任务列表中与委托人一起展示
- 任务标记保存在独立字段中，自定义标签名称和系统分配的唯一颜色保存在 `quest_labels` 表中
- 编辑互斥关系时只需按任务名搜索并选择另一个任务，系统会自动生成组和 A/B 路线并同步更新双方
- 旧版 SQLite 首次启动时会自动增加新字段，并从原备注迁移已有的限时与互斥信息
- 页面新增、编辑、批量导入和恢复初始数据都会直接写入 SQLite
- SQLite 文件和 JSON 初始数据均可提交到 Git；SQLite 是二进制文件，不适合多人同时修改后合并
- 提交 Git 前先停止 `npm run dev`，确保 SQLite 已把最新修改写回数据库文件
- 生产环境需要使用 Node.js 服务器并提供持久化磁盘；普通 SQLite 文件不能直接部署到 Cloudflare Workers
- 建议在重要修改后使用页面的“导出”功能保存一份 JSON 备份

如需重新抓取蒙纳多研究本部的补充数据，可运行以下命令；结果会写入 `data/xc1-quests-xenoblade-cn.json`，不会覆盖 523 条完整目录：

```bash
python scripts/fetch_xc1_quests.py
```

抓取完成后，可用游戏内部编号和英文数据表重新执行高置信度合并，并同步本地 SQLite：

```bash
python scripts/enrich_xc1_quests_from_cn.py --apply
```

如需从乐园数据管理室重新生成《异度神剑 2》目录，可运行：

```bash
python scripts/fetch_xc2_quests.py
```

脚本会校验总数、任务类型、本篇/扩展票/《黄金之国伊拉》归属，并确保所有记录均不带限时或互斥属性；生成结果写入 `data/xc2-quests.json`，应用下次启动时会自动补充缺少的生成数据。

如需从送行者的收集手册重新生成《异度神剑 3》目录，可运行：

```bash
python scripts/fetch_xc3_quests.py
```

脚本会核对主线剧情 7 条、英雄任务 42 条、普通任务 155 条和《崭新的未来》42 条的主站目录基准，再逐页提取任务条件、推荐等级、奖励与流程。最终结果会校验为本篇 198 条、扩展票追加 6 条、《崭新的未来》42 条，并写入 `data/xc3-quests.json`；抓取缓存保存在 Git 忽略的 `work/xc3-cache` 中。

## 离线 PWA 与完整备份

电脑模式仍使用 `npm run dev` 和 `data/xeno-archive.sqlite`（或 `SQLITE_DATABASE_PATH`）。
新增的 PWA 模式为独立静态构建，在浏览器内通过 sql.js 运行同一套 SQLite 业务逻辑，
将数据库保存到当前站点的 IndexedDB；不请求在线业务接口，不会同步或覆盖电脑数据库。
浏览器需要支持 WebAssembly、IndexedDB 和 Web Locks，建议使用最新 iOS/Safari。

### 首次迁移到 iPhone

1. 在电脑模式打开侧栏的“完整备份与恢复”，点击“生成完整备份”，再点击“保存备份”。
2. 把完整备份 JSON 保存到 iCloud Drive 或传到手机。“导出任务”只导出任务，不能代替完整备份。
3. 用 iPhone Safari 打开发布地址，添加到主屏幕并开启“作为 Web App 打开”。
4. **从主屏幕图标进入**，打开“完整备份与离线管理”，等到“离线资料已就绪”。
5. 选择完整备份，核对备份时间、任务和笔记数量，确认覆盖并恢复。导入后自动刷新。
6. 开启飞行模式，测试查询、笔记和进度。外部资料来源链接仍需要网络。

完整备份包含所有作品的任务与手动修改、标签、笔记、NPC 与任务关联、XC1/XC2 地点探索与收藏、
XC2 角色收集与收藏，以及内部数据迁移标记。图片和只读图鉴目录随应用发布，不重复放进备份。
导入是**完整替换，不是合并**；先导出目标设备当前数据，保存未提交的编辑。
格式版本、字段、关联和数据库约束校验失败时，恢复事务回滚；手机只有在 IndexedDB 成功保存后才报告成功。

之后直接在手机 Web App 中生成、保存、导入备份，无需电脑中转。Safari 标签页与主屏幕 Web App
可能使用不同的存储空间；请始终从日常使用的入口进行导入和备份。清理网站数据、删除 Web App 或换设备前先备份。
不自动同步其他设备，不承诺浏览器本地数据永不被系统回收。完整备份文件包含个人数据，请勿放进公开仓库。

### 构建和验证

```bash
npm run dev:pwa       # 仅开发调试，不启用 Service Worker
npm run build:pwa     # 生成 dist-pwa/，包含离线资源和 Service Worker
npm run preview:pwa   # 浏览器通过 localhost:4173 测试生产离线模式
```

发布到仓库子路径时，在 PowerShell 中使用：

```powershell
$env:PWA_BASE_PATH = '/xb-manual/'  # 替换成实际 GitHub 仓库名
npm run build:pwa
npm run preview:pwa
```

此时预览地址为 `http://localhost:4173/xb-manual/`。根域名站点使用 `/`。
离线功能要求 HTTPS（本机 localhost 例外）；手机访问电脑的普通 HTTP 局域网地址不能用于完整离线安装验证。
应用内部栏目由 React 在同一页面中切换；资料来源等外站链接打开浏览器是预期行为。

### 发布到 GitHub Pages

项目已提供 `.github/workflows/pages.yml`：推送 `main` 且包含程序、基础资料、静态资源、脚本、测试或构建/发布配置改动时，构建并上传 **dist-pwa/**。
仅修改 README、Markdown 文档或其他未列入工作流 `paths` 的文件时，不自动部署。
文档与程序一起修改时仍会部署。GitHub Actions 中的手动发布入口始终保留，不受路径筛选限制。
工作流自动读取 Pages 的站点子路径，无需把仓库名写死进代码。

代码仓库：https://github.com/gongtp/xb-manual-pwa

手机访问：https://gongtp.github.io/xb-manual-pwa/

当前工作目录直接使用 GitHub 的干净历史，`origin` 仅指向上述 GitHub 仓库。
修改代码后在本目录测试、提交并 `git push origin main`，Actions 自动发布；不再同步临时发布副本。
原 Gitee 仓库暂时保留，不再向其推送，也不要合并旧仓库历史。

`data/` 中受版本控制的 JSON/TS 是公开基础资料。页面内的个人修改保存在
`data/xeno-archive.sqlite`，数据库文件始终留在本地，不参与提交。
完整备份和任务导出统一保存到本地 `backups/`（整个目录已忽略），或项目目录之外。
不要将个人记录写进公开基础资料文件，也不要使用 `git add -f` 强制添加数据库或备份。

本机已启用 `.githooks/pre-push`，检查推送目标、提交历史中的数据库路径和完整备份格式。
新克隆时运行 `git config core.hooksPath .githooks` 启用同样的保护；也可手动运行 `npm run check:public`。
忽略规则与检查是防误操作保护，不会识别任意改名或改写的个人内容，提交前仍应查看差异。

迁移产生的旧 Git 历史、数据库快照和临时发布副本已清理；本地保留当前 GitHub 代码及个人主数据库。
电脑与手机数据库彼此独立，更新网站不会同步或覆盖个人数据；需要迁移时使用完整备份。

### 清理 GitHub 部署记录（Windows）

双击 `manage-deployments.cmd`：输入 `1` 查询，`2` 选择删除，`0` 退出。
删除时可输入序号（多个用逗号分隔）或 `all` 选择全部可删除记录，最后输入 `DELETE` 确认。
只清理 `gongtp/xb-manual-pwa` 的 `github-pages` 环境，保护成功的 Active、进行中和状态未知的记录。
使用已有 Git 凭据管理器，可能弹出登录窗口；不安装软件、不保存令牌到项目。
如凭据权限不足，需给该仓库授予 Deployments 读写权限（也支持运行前设置 `GITHUB_TOKEN` 环境变量）。
此工具不提交、不推送、不触发部署，不删除 Actions 运行日志，也不修改个人数据库。
部署记录删除后不能恢复；中途失败时，已删除的记录不会回滚，可输入 `1` 重新查询。

### 更新与数据安全

新版本完整缓存成功后，离线管理中会出现“应用已下载的新版本”。先保存编辑，再应用更新；
此操作仅更新程序和基础资源，不清除 IndexedDB 中的进度与笔记，无需删除桌面图标。
下载失败时继续使用旧版本，可联网后点击“检查更新 / 重试下载”。
初次离线准备会下载所有内置图像，完成前请保持应用打开。

`npm test` 使用从基础资料初始化的临时数据库，不读取或修改当前个人数据库；包含完整备份的桌面/浏览器往返与损坏备份回滚验证。
